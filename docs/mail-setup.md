# Подключение заявок сайта

Обе формы отправляют JSON в `/api/inquiry.php`. Тип `general` — общая заявка из футера; `product` — запрос цены с выбранным товаром, фасовкой и количеством. Количество может отсутствовать при открытии формы из каталога. Email в общей форме необязателен, телефон обязателен; в запросе товара обязателен email.

Получатель всегда `seha.info@inbox.ru`. Отправитель — технический ящик `info@seha-group.ru`. Ответ менеджера направляется на email покупателя через Reply-To, если он указан. Сайт не отправляет покупателю автоматические письма.

## Однократная настройка на REG.RU

1. В менеджере файлов откройте `/www/seha-group.ru/api/private/config.php`. Автоматическая публикация создаёт его с выключенной отправкой и пустым паролем, только если файла ещё нет.
2. Укажите SMTP-сервер и пароль ящика `info@seha-group.ru`. Для почты на виртуальном хостинге REG.RU исходящие настройки: `mail.hosting.reg.ru`, порт `465`, SSL. Если ящик обслуживается другой почтовой платформой, используйте её SMTP-настройки.
3. В `username` и `from` оставьте полный адрес этого ящика. В `password` укажите его SMTP-пароль. Для PHP-строки в одинарных кавычках символы `\` и `'` в пароле нужно экранировать как `\\` и `\'`.
4. После заполнения установите `'enabled' => true` и сохраните файл. Пароль не добавляйте в GitHub, браузерные переменные или переписку.
5. Отправьте по одной заявке из футера и карточки. Убедитесь, что обе пришли на `seha.info@inbox.ru`, товар и количество сохранены, а «Ответить» подставляет адрес покупателя. Проверьте также папку «Спам».

До настройки обработчик возвращает ошибку 503; интерфейс не сообщает об успешной отправке. Сохранение настроек само по себе не подтверждает доставку — нужна проверка реальных писем. SMTP-подтверждение означает приём письма почтовым сервером, а не гарантию попадания во «Входящие».

## Публикация и защита

GitHub Actions отдельно обновляет PHP-обработчик и PHPMailer 7.2.0, затем сайт. Заполненный `config.php` не перезаписывается. Папка `api/private` закрыта от HTTP-запросов через `.htaccess`, просмотр каталогов отключён. Данные проверяются на сервере; получателя нельзя подменить из формы. Включены проверка источника, ловушка для ботов и ограничение частоты обращений. Содержимое заявок и SMTP-пароль в журналы приложения не записываются.

Единственный обработчик отправки — PHP в `server/php/`. Node.js используется только для сборки сайта и проверок интерфейса.
