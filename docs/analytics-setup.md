# Подключение Яндекс Метрики

## Что сейчас есть

Счётчик Метрики, его номер и вызовы `ym` в проект пока не добавлены. Обе формы отправляют заявки через PHP. Успешная отправка подтверждается ответом `{ "success": true }` после приёма письма SMTP-сервером.

Cookie-уведомление сейчас сохраняет `seha-cookie-consent=dismissed`: и крестик, и кнопка скрывают уведомление. Это не отдельное согласие на аналитику. Политика конфиденциальности пока прямо сообщает, что аналитика не загружается.

## Рекомендуемая настройка

1. Создать счётчик в аккаунте Яндекса компании на https://metrika.yandex.ru/. В поле «Адрес сайта» указать `seha-group.ru` без `https://`, часовой пояс — Москва. Доступ подрядчику выдать отдельно, без передачи пароля аккаунта.
2. Ограничить сбор доменом seha-group.ru; локальный просмотр исключить из аналитики, чтобы тестовые посещения не смешивались с рабочими.
3. Для начала включить просмотры страниц, переходы и карту кликов. Вебвизор и запись содержимого форм оставить выключенными. Имена, email, телефоны и сообщения покупателей в параметры Метрики не передавать.
4. Создать две цели типа «Целевое событие»: `footer_inquiry_sent` и `product_inquiry_sent`. Вызывать их после успешного ответа обработчика, а не по нажатию кнопки и не по обычному событию submit. Автоматическая цель отправки формы может учитывать неуспешные попытки.
5. Перед загрузкой счётчика разделить согласие и закрытие уведомления: закрытие не включает аналитику; явное согласие включает. Старое значение `dismissed` не считать согласием. Предусмотреть возможность изменить выбор.
6. При подключении обновить русскую и английскую политику: указать Яндекс Метрику, назначение аналитики и порядок отказа. Текущую фразу об отсутствии аналитики заменить.

## Что нужно для завершения

Передать номер счётчика (число из настроек Метрики, не пароль). Затем добавить загрузку счётчика в общий шаблон после согласия, вызовы двух целей в успешные сценарии форм и обновить уведомление и политику. Номер можно хранить в публичной переменной сборки; SMTP-пароль к аналитике отношения не имеет.

После публикации проверить отсутствие запросов к Метрике до согласия, появление посещения после согласия и по одному достижению каждой цели после успешной заявки. Ошибка SMTP, ошибки заполнения и простой клик по кнопке не должны считаться отправленной заявкой. Для проверки использовать тестовые обращения и сверять их с реальными письмами.

Официальные инструкции: [установка счётчика](https://yandex.ru/support/metrica/ru/general/creating-counter), [целевое событие](https://yandex.ru/support/metrica/ru/general/goal-js-event), [особенности цели «Отправка формы»](https://yandex.ru/support/metrica/ru/simple-goal/form).
